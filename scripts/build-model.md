# Build the golfer assets

Run these commands from the repository root. The source files and their recorded provenance are in [assets-src/README.md](../assets-src/README.md). The current conversion ran with Blender **5.2.1**, although the original tooling specification named Blender 4.x. The script uses the installed version's action slots and NLA export API; Blender 4.x compatibility has not been established.

## Rebuild

Use an installed Blender executable with FBX import and glTF export support:

```bash
blender --background --python scripts/build-model.py
```

On this macOS installation, the executable can also be invoked as:

```bash
/Applications/Blender.app/Contents/MacOS/Blender --background --python scripts/build-model.py
```

The script imports the skinned T-pose mannequin, clears its source action, normalizes `mixamorig1:` bone and vertex-group prefixes, replaces the mesh materials with one rough matte material and imports the three selected motion actions. It exports named NLA tracks with sampling and times shifted to zero. It then renders five transparent front-view PNGs for each action and saves a Blender working file.

Outputs:

- `assets-src/golfer-raw.glb`: texture-free export before compression.
- `assets-src/model-report.json`: clip/source mapping, source frame ranges, durations, triangle count and raw byte count.
- `assets-src/golfer.blend`: generated working scene.
- `public/models/poster/{full,chip,putt}/{0,1,2,3,4}.png`: 720 × 960 phase frames.

Compress the raw export as a separate step:

```bash
bunx @gltf-transform/cli optimize assets-src/golfer-raw.glb public/models/golfer.glb --compress meshopt --texture-compress webp
```

This is the command used for the current asset. There are no model textures to convert; the texture option has no texture payload to process. The CLI was resolved through `bunx` rather than pinned in the repository, so identical-byte regeneration across future CLI versions is not guaranteed. Keep the raw export outside `public/`.

## Motion mapping

| Action | Source | Duration | Poster sample times |
| --- | --- | --- | --- |
| `full` | `golf-drive-2.fbx` | 3.4 s | 0, .12, .24, .33, 1 |
| `chip` | `golf-chip-2.fbx` | 58/30 s | 0, .12, .28, .4, 1 |
| `putt` | `golf-putt-3.fbx` | 2.4 s | 0, .12, .28, .4, 1 |

`GOLF_CLIPS` can override the source mapping for triage:

```bash
GOLF_CLIPS='{"full":"golf-drive-2.fbx","chip":"golf-chip-2.fbx","putt":"golf-putt-3.fbx"}' blender --background --python scripts/build-model.py
```

This regenerates outputs in place. Preserve the runtime action names. If selections or phase markers change, update `src/lib/swing-data.ts` and the poster sampling in `scripts/build-model.py` together. The runtime uses the first frame as Address; it does not export a separate address animation. Pitch and bunker currently share the chip action and must retain their qualification in the instructional copy.

The 17-input inventory is in `assets-src/triage.json`; the 16 animation variants each have 11 sampled poses in `assets-src/poses.json`. These are triage records, not outputs regenerated by `build-model.py`.

## Verify before shipping an updated asset

Inspect the GLB for one mesh primitive, one material, no textures, the three named clips, and meshopt decoding support. The current compressed asset is 348,144 bytes; the source mannequin is 28,880 triangles and the raw export is 1,351,376 bytes. Check the ≤3 MB asset budget and ≤30k mannequin triangle budget after every rebuild. Measure complete-scene draw calls separately, including the club, ground and overlays, against the eight-call budget.

Compare all 15 posters with their runtime phases. Check wrist attachment, handedness, all camera presets and both overlays. Run `bun run build` to refresh the static export and precache manifest. The precache warns above 6 MiB; its latest recorded total was 8.89 MiB. The model itself is within its byte budget.

Use `?poster` to force the fallback and `?debug` to expose the read-only `window.__rangeNotesViewer` snapshot in a production build. Neither mode provides phone frame-time, memory or load measurements. Physical-phone performance and the overlay overhead threshold remain pending; see [the spike record](../docs/spike-3d-golfer.md).

## Posters

The five fallback frames per clip are no longer rendered in Blender. With a production server running (`bun run start`), run `node scripts/build-posters.mjs` to photograph the live scene at each phase marker into `public/models/poster/`. Set `CHROMIUM_PATH` if Playwright's bundled Chromium is not installed.
